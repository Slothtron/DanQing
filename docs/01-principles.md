# 01 · 设计原则与命名规范

## 1. 六条设计原则

### 原则一：色彩必须有出处

每一个原语色值都能回答「它为什么是这个颜色」。锚点级直接等于某条传统色原值，其余级是该色在感知空间中的明度延伸。
不存在「调着调着觉得好看就定下来」的颜色。

> 检验方式：`dist/reports/ramp-report.md` 里每一级都列出了最近的传统色名与原始色值。

### 原则二：语义先于颜色

讨论界面时先确定**这是什么**（主操作 / 危险 / 元信息），再选色。禁止出现「把那个蓝色调深一点」这类需求——
应该说「主操作的按下态不够明显」。

### 原则三：可读性不可协商

任何前景/背景组合都要过 WCAG 门禁（正文 4.5:1，非文本 3:1）。门禁失败时调整的是**颜色**，不是门禁。

> 注意半透明：文字常用 `rgba(ink, 0.68)` 这类写法，真实观感取决于合成后的颜色。
> 丹青的门禁会先把 alpha 合成到背景再算对比度，而不是忽略 alpha。

### 原则四：深色不是浅色的反相

浅色模式的基底是**素**（纸），深色模式的基底是**墨**（夜）——两者是不同材料，不是同一材料的明度翻转。
因此深色的表面层级靠**提亮**堆叠（`#101318` → `#14171C` → `#1E2732` → `#252D3A`），而不是把浅色的投影变暗。

### 原则五：结构上避免语义冲突

状态色占用**保留族**，品牌只在非保留族取色。这使「品牌主色恰好等于成功色」在结构上不可能发生，
而不是靠文档里写一句「请注意不要撞色」。

### 原则六：一个真源，机器生成

`tokens/source.json` 是唯一人手维护的文件，产物由生成器写出。
不允许任何人手改产物（终端配色同样如此，改了下一次构建就覆盖），也不允许任何端有「自己那份色值」。

## 2. 命名规范

### 2.1 中文名（人的语言）

色族与色名取自传统色，保留汉字与拼音：

| 层 | 命名形态 | 例子 |
|---|---|---|
| 色族 | 单字，传统色系名 | 青 / 朱 / 缃 / 绿 / 绛 / 黛 / 苍 / 紫 / 檀 / 墨 / 素 |
| 色级 | 族 + 级数，且每级附最近传统色名 | `qing-700` = 群青（Qún Qīng） |
| 语义角色 | 功能词，不用颜色词 | `text.primary`、`danger.default`、`state.hover` |

**禁止**用「浅蓝」「深红」「橙色」这类颜色词命名语义角色。语义角色的名字要能回答「用在哪」，
而不是「看起来像什么」。

### 2.2 令牌 id（机器的语言）

```
tier1  cn.{family}.{step}          例：cn.qing.700      （仅在 source/生成物内部使用）
tier2  sys.{role}.{variant}        例：sys.text.primary
tier3  ext.{domain}.{name}         例：ext.reading.bg
```

令牌前缀是 `dq`（真源里的 `meta.prefix`）。各端拿它作为自己那套变量的命名空间，点号转连字符：

```
sys.text.primary    →  dq-text-primary
sys.primary.default →  dq-primary-default
cn.qing.700         →  dq-cn-qing-700
```

前缀不随品牌或主题变化。终端配色是唯一不走这层命名的产物——它按 Windows Terminal
自己的字段名输出，见 [`06-terminal-theming.md`](./06-terminal-theming.md)。

级数使用 50–950 的百位制（Tailwind 惯例），便于跨系统交流；`950` 用于最深的强调底。

### 2.3 传统色名反查

每一级色阶都会在 384 条传统色中寻找 OKLab 欧氏距离最近的一条，记录为 `name` / `pinyin` / `nearestHex` / `nearestGroup`。

反查结果**不参与**令牌 id（避免一色多名导致 id 漂移），只用于：
- 人在读报告时能对上「哦这是月白」
- 设计评审时说「这里用的是窃蓝」而不是「#92B2EB」

## 3. 用色禁区

| 禁止 | 原因 | 应该怎么做 |
|---|---|---|
| 在界面代码里写 tier1 或字面色值 | 换品牌/换主题时必然漏改 | 引用 `sys.*` 语义令牌 |
| 用颜色承载唯一信息 | 色盲用户无法区分 | 状态色必须同时有图标或文案（WCAG 1.4.1） |
| 用「绛」表示强调、「朱」表示危险 | 两者同色相，极易混淆 | 强调用 `紫`（accent），危险用 `绛`（danger） |
| 用纯黑 `#000` 作正文 | 与暖白背景对比过硬，长看刺眼 | 用 `墨-900` `#1E2732` |
| 用纯白 `#FFF` 作浅色页面底 | 与卡片无法分层，且眩光强 | 页面底用 `素-100` `#E4E1D8`，卡片用 `#FFFFFF` |
| 大面积使用高饱和主色 | 中式审美重「留白」与「克制」 | 主色用于操作与选中，面积占比建议 < 10% |
| 同一个界面出现两种强调色 | 强调失去意义 | 一次只用一个强调色 |
| 直接改生成出来的文件（终端配色也一样） | 下次生成即被覆盖 | 改 `tokens/source.json` 后重跑 `danqing build` |

## 4. 色彩面积与节奏（非强制，但强烈建议）

中国传统绘画的色彩观是「随类赋彩」——颜色跟着物象的类别走，而不是铺满画面。落到界面：

| 层级 | 占比 | 用途 |
|---|---|---|
| 基底 | 70–85% | 页面底、大面积表面、留白（素/墨） |
| 结构 | 10–20% | 卡片、分隔、描边、次级文字（素阶深色 / 墨阶浅色） |
| 强调 | 5–10% | 主操作、当前选中、关键数字（品牌色） |
| 点题 | < 2% | 状态提示、徽标、印记（状态色） |

超过这个比例时，先问「是不是把强调色当背景色用了」。

## 5. 无障碍与包容性基线

| 项 | 基线 |
|---|---|
| 正文对比度 | ≥ 4.5:1（AAA 目标 7:1） |
| 大字号（≥18.66px 粗体 / ≥24px） | ≥ 3:1 |
| 非文本（边框、图标、图形） | ≥ 3:1 |
| 三级文字 | ≥ 3:1 |
| 触控目标 | ≥ 44×44 pt/dp（提供 `scale.touch.comfortable = 48`） |
| 色盲 | 状态色必须附图标或文案；图表色序已避开红绿相邻（见 `02-color-system.md` §7） |
| 动效 | `prefers-reduced-motion` 下所有位移/缩放归零，仅保留 ≤80ms 颜色淡变 |
| 焦点 | 必须有可见焦点环（`focus.ring` + `focus.offset` 2px 偏移），不得 `outline: none` 了事 |
