# 02 · 色彩系统

## 1. 为什么是「五方正色」

中国传统色彩体系不是色相环，而是**「正色 / 间色」的等级观**：

> 《礼记·玉藻》：正色为青、赤、黄、白、黑 —— 五方五行之色；间色为绀、红、缥、紫、流黄等，由正色相杂而成。

这套观念对设计系统有两点直接价值：

1. **正色有语义，间色有情绪。** 正色（青赤黄白黑）适合承担「功能含义」，间色（紫、缥、缃、檀）适合承担「氛围」。
2. **正色是有限的。** 「五色」本身就是一个受约束的调色板——这与设计系统追求的「色彩数量有限、用法明确」高度一致。

丹青的 11 个色族即由此出发：以五方正色的现代转译为主体（青/朱/缃/绿/绛/墨/素），
补入 4 个间色（黛/苍/紫/檀）用于扩展表达，并为「信息」「强调」「品牌」三类角色预留互不重叠的色族。

## 3. 色阶生成算法（可复现）

11 级（50 / 100 / 200 / 300 / 400 / 500 / 600 / 700 / 800 / 900 / 950），每族一条完整色阶。算法在 Rust 生成器 `src/model.rs` 的 `build_families` 中，共五步：

### 3.1 确定锚点落位

把锚点色转到 OKLCh，取其 **L**，在预先定义的 11 点感知明度网格中找最近的一格：

```
GRID_L = [0.975, 0.910, 0.836, 0.762, 0.688, 0.614,
          0.540, 0.466, 0.392, 0.300, 0.215]
```

例：群青 `#2E59A7` 的 L ≈ 0.534 → 落在索引 6 → **第 700 级**。

### 3.2 锚点级写回原值（锚点保真）

网格格点只是位置。**锚点那一级直接使用传统色原值，不取网格推导值**：

```
qing-700 = #2E59A7   ← 群青原值，不是推导值
```

这是「色彩必须有出处」最硬的落实：11 个传统色原值在 121 个原语里逐字保留。

### 3.3 其余级按感知明度派生

对非锚点级，保持色相 H 不变，改变 L，并按距离锚点的远近**衰减彩度**：

```
taper = max(0.10, 1 − 0.90 · |Δd|^1.6)
C(新级) = C(锚点) · taper
```

彩度衰减是必要的：若恒定高彩度往上推，亮部会变成荧光色；往下推，暗部会变成死黑。
`|Δd|^1.6` 让近锚点级几乎不掉彩度、远锚点级快速收敛到近中性。

### 3.4 收进 sRGB 色域

OKLCh 里合法的高彩度色在 sRGB 中常常不可表达。算法用**二分法降彩度**（最多 28 次迭代）
找到仍能落进色域的最大 C，保证输出的十六进制色值没有裁剪失真。

### 3.5 反查传统色名

把生成出的每一级在 384 条传统色中做 OKLab 欧氏距离最近邻搜索，记录名称/拼音/原值/色系。

例：`qing-500 = #5A83CC` 最近邻是 **紫苑** `#757CBB`（OKLab 距离 0.036）。
这说明该级在感知上更接近「紫苑」而非「群青」——这类信息对设计评审很有用：
它告诉你这一级已经偏紫了，如果需要一个「更纯的蓝」应该往 600–700 走。

> 全部 121 级的反查结果见 `dist/reports/ramp-report.md`。

## 4. 锚点保真 vs 可读性：自动回退机制

有了色阶，还需要决定「主色按钮用哪一级」。这里有一个真实的取舍：

- 用**锚点级**（如银朱 `#D12920`）：品牌识别度最高，但白字压在上面的对比度可能刚好不足 4.5:1。
- 用**更深的级**：可读性达标，但颜色偏离了传统色。

丹青的规则是：**优先锚点，不达标才沿色阶向外回退，并把回退步数记录下来。**

选中「填充级」的条件有两个，必须同时满足：

1. 与页面底色对比度 ≥ **3.0:1**（按钮边界可辨，WCAG 1.4.11 非文本对比）
2. 其上文字（白 `#FFFFFF` 或墨 `#0E1116` 中较优者）对比度 ≥ **4.5:1**

实测结果（`dist/reports/ramp-report.md`）：

| 品牌 | 色族 | 模式 | 填充级 | 回退 | 填充色 | 其上文字 | 对比度 |
|---|---|---|---|---|---|---|---|
| 群青（默认） | 青 | light | 700 | **+0** | `#2E59A7` | `#FFFFFF` | 6.77:1 |
| 群青 | 青 | dark | 600 | −1 | `#416CBA` | `#FFFFFF` | 5.15:1 |
| 银朱 | 朱 | light | 600 | **+0** | `#D12920` | `#FFFFFF` | 5.19:1 |
| 银朱 | 朱 | dark | 600 | **+0** | `#D12920` | `#FFFFFF` | 5.19:1 |
| 青黛 | 黛 | light | 800 | **+0** | `#45465E` | `#FFFFFF` | 9.17:1 |
| 青黛 | 黛 | dark | 600 | −2 | `#6B6C84` | `#FFFFFF` | 5.12:1 |
| 檀色 | 檀 | light | 500 | **+0** | `#B26D5D` | `#0E1116` | 4.72:1 |
| 檀色 | 檀 | dark | 500 | **+0** | `#B26D5D` | `#0E1116` | 4.72:1 |

三个值得注意的结论：

1. **六个组合里五个零回退**，锚点保真度很高。只有暗色模式下的青、黛需要外移 1–2 级——
   因为它们本身的明度不够撑起深色底上的边界。
2. **「填充上的文字」不预设为白色。** 檀色在最亮与最暗两个极端里择优，得到「赭褐底 + 墨字」，
   这比强行用白字（3.79:1，不达标）高明得多。深色模式下的紫同理（`#9C73A3` 底 + 墨字）。
3. 早期版本曾把 `on` 色限制为单一方向（浅色模式白字、深色模式墨字），结果紫族在暗色下
   **没有任何一级**能同时满足边界 3:1 与文字 4.5:1，只能退化到近白色填充。改为双极端择优后问题消失。

## 5. 中性色：Alpha 阶梯

除了色族的实色阶，系统还有一套**基于当前模式墨色的 alpha 阶梯**，用于所有「半透明灰」需求：

```jsonc
// 浅色模式 inkRgb = "30,39,50"（瑾瑜）；深色模式 inkRgb = "212,229,239"（月白）
"border": { "subtle": "rgba(@inkRgb,0.08)", "default": "rgba(@inkRgb,0.14)", "strong": "rgba(@inkRgb,0.28)" },
"text":   { "secondary": "rgba(@inkRgb,0.68)", "tertiary": "rgba(@inkRgb,0.55)", "disabled": "rgba(@inkRgb,0.34)" },
"state":  { "hover": "rgba(@inkRgb,0.04)", "pressed": "rgba(@inkRgb,0.08)",
            "selected": "rgba(@inkRgb,0.12)", "drag": "rgba(@inkRgb,0.16)", "disabled": "rgba(@inkRgb,0.05)" }
```

这套机制的价值在于**自动适配**：同一个 `sys.border.default` 在浅色下是「深灰 8%」，
在深色下是「浅灰 9%」——因为 `@inkRgb` 随模式翻转。
如果用两套固定的实色，深色主题的描边十有八九会写成「浅色模式的值 + 手调」，
然后在某个页面上显得突兀。

> 门禁会对这些 alpha 值先做合成再测对比度，不达标直接失败。

## 6. 保留族机制：从结构上避免语义冲突

一个常见的严重问题：产品品牌色选了绿色，而系统里「成功」也是绿色——用户无法仅凭颜色区分
「主操作」与「操作成功」。

丹青的解法是把色族分成两类：

```jsonc
"reservedFamilies": {
  "map": { "accent": "zi", "success": "lv", "warning": "xiang", "danger": "jiang", "info": "cang" },
  "neutral": ["mo", "su"]
}
```

**保留族**（紫/绿/缃/绛/苍）与**中性族**（墨/素）不参与品牌；品牌只在 `qing / zhu / dai / tan` 中取色。
生成器会检测冲突并写入报告——当前结果是**零冲突**。

如果确实需要一个「绿色品牌」，正确做法是新增一个非保留的绿色族（例如以「竹青」为锚点），
而不是复用 `lv`。

## 7. 数据可视化色序

`sys.chart.c1…c10` 是一条 10 色序列，按**青绿山水 → 暖褐**的冷暖顺序排列，并刻意避开了红绿相邻：

| 序 | 传统色 | 浅色模式 | 深色模式 |
|---|---|---|---|
| c1 | 群青 | `#2E59A7` | `#6B8FD4` |
| c2 | 铜青 | `#3D8E86` | `#4FB3A6` |
| c3 | 官绿 | `#2A6E3F` | `#4E9C63` |
| c4 | 秋香 | `#BF9C46` | `#D4B36A` |
| c5 | 柘黄 | `#C67915` | `#DE9A45` |
| c6 | 银朱 | `#D12920` | `#E4665C` |
| c7 | 红踯躅 | `#B83570` | `#D9739E` |
| c8 | 紫紶 | `#7D5284` | `#A98BC0` |
| c9 | 檀色 | `#B26D5D` | `#D69A86` |
| c10 | 檀褐 | `#945635` | `#C08A6B` |

另外提供 `grid` / `axis` / `label` / `positive` / `negative` / `neutral` 六个图表辅助色。

图表色是**字面值**（不来自色阶），因此生成器会额外校验它们与底色的对比度（≥ 3:1），
不达标就在 OKLCh 中自动调整明度并记录修正——当前无需修正。

## 8. 深浅两套基底的构造

| 语义 | 浅色（素 / 纸） | 深色（墨 / 夜） |
|---|---|---|
| 画布底 `bg.canvas` | 凝脂 `#F5F2E9` 更浅一级 | `#101318` |
| 页面底 `bg.base` | 凝脂 `#F5F2E9` | `#14171C` |
| 凹陷 `bg.sunken` | 素阶 200 | `#0E1116` |
| 卡片 `surface.default` | `#FFFFFF` | 瑾瑜 `#1E2732` |
| 抬升 `surface.raised` | `#FFFFFF` | 素阶 800 |
| 变体表面 `surface.variant` | 素阶 200 | 素阶 800 |
| 正文 `text.primary` | 瑾瑜 `#1E2732` | 素阶 50 |
| 反白 `text.inverse` | 素阶 50 | `#1E2732` |

深色模式的表面层级靠**提亮**实现（`#101318` → `#14171C` → `#1E2732`），
层级越高的表面越亮、越接近用户；浅色模式则靠**白度**与阴影实现。
