# 05 · 无障碍

## 1. 「可验」优于「可信」

设计系统的无障碍最容易犯的错是**声明式**的：文档里写「我们的对比度符合 WCAG AA」，
但没有任何东西能阻止下一个人加一个不达标的颜色。

丹青把无障碍做成**构建门禁**：`danqing build` 每次运行都会实测全部门禁，
任何一项失败即返回退出码 1。CI 里只要接这一条命令，不合规的颜色就进不了主干。

```bash
danqing build || exit 1              # 当前：108 项，失败 0 项
```

## 2. 门禁怎么算

### 2.1 阈值

| 类别 | 阈值 | 依据 |
|---|---|---|
| 正文、重要文字 | ≥ 4.5:1 | WCAG 2.1 AA · 1.4.3 |
| 状态色文字 / 页面底 | ≥ 4.5:1 | 同上（状态色文字也是正文级） |
| 填充上的文字（`on`） | ≥ 4.5:1 | 同上（按钮标签是正文级） |
| 三级文字、图表色、填充边界 | ≥ 3.0:1 | WCAG 2.1 AA · 1.4.11 非文本对比 |

### 2.2 半透明必须先合成

这是丹青门禁与多数实现的关键差别。`text.secondary` 是 `rgba(30,39,50,0.68)`，
它在白色卡面上的真实观感是**合成后**的 `#63696D`，而不是墨色本身。

如果直接拿 `#1E2732` 去算对比度，会得到 15.09:1 的漂亮数字——但那不是用户看到的。
丹青先做 alpha 合成再计算，因此测出的是 5.30:1，仍有充裕余量，但这个数字是真实的。

```python
def contrast(fg, bg):
    base = composite(bg, "#FFFFFF")          # 背景若半透明，先合成到白
    return contrast_raw(fg, rgb_to_hex(base))  # fg 的 alpha 在 composite 内合成
```

### 2.3 覆盖范围

| 分组 | 项数 | 检查内容 |
|---|---|---|
| 文字 | 8 | 正文/次要/三级文字 × 浅深 × 页面底与卡面 |
| 状态色 | 40 | accent/success/warning/danger/info × 浅深 × {填充上文字、文字/页面底、文字/浅底、填充/页面底} |
| 数据可视化 | 20 | chart c1–c10 × 浅深 × 与页面底 |
| 品牌 | 32 | 4 品牌 × 浅深 × {填充上文字、文字/页面底、文字/浅底、填充/页面底} |
| 扩展 | 8 | 4 纸色 × {正文、次要文字} |
| **合计** | **108** | |

新增品牌、新增色族、新增扩展时，门禁项数会自动增长——**新颜色不可能绕过检查**。

其中「文字 / 浅底」这一组是后期补上的：早期只校验「文字 / 页面底」，而界面里
「浅底深字」才是选中态与徽标的主要形态。实测中 `warning.text` 压在 `warning.subtle`
上只有 3.96:1——12px 徽标文字不达 AA，而只查页面底完全看不出来。补上这 18 项
（状态色 +10、品牌 +8）后，合计 90 → 108。

## 3. 实测结果

完整表格见 `gen/reports/contrast-report.md`。摘要：

### 3.1 文字（最关键的 8 项）

| 检查项 | 实测 | 要求 | 余量 |
|---|---|---|---|
| 浅色 · 正文 / 页面底 | 13.48:1 | ≥4.5 | +199% |
| 浅色 · 正文 / 卡面 | 15.09:1 | ≥4.5 | +235% |
| 浅色 · 次要文字 / 卡面 | 5.30:1 | ≥4.5 | +18% |
| 浅色 · 三级文字 / 卡面 | 3.56:1 | ≥3.0 | +19% |
| 深色 · 正文 / 页面底 | 16.05:1 | ≥4.5 | +257% |
| 深色 · 正文 / 卡面 | 13.48:1 | ≥4.5 | +199% |
| 深色 · 次要文字 / 卡面 | 6.77:1 | ≥4.5 | +50% |
| 深色 · 三级文字 / 卡面 | 4.70:1 | ≥3.0 | +57% |

正文全部达到 **AAA（≥7:1）**。次要文字留有 18% 以上余量——这个余量是刻意的，
因为设计实践中常有「把 secondary 稍微调淡一点」的冲动，余量给出调整空间。

### 3.2 需要留意的紧项

| 检查项 | 实测 | 说明 |
|---|---|---|
| 浅色 · 图表 c4 / 页面底 | 3.06:1 | 秋香原值 `#BF9C46` 与暖白底仅 2.7:1，生成器已在 OKLCh 中降明度到 `#A9862E` |
| 浅色 · 图表 c5 / 页面底 | 3.05:1 | 柘黄 `#C67915` 原值本身刚好达标，**不要**再调亮 |
| 浅色 · 三级文字 / 卡面 | 3.56:1 | alpha 0.55，若调到 0.50 会跌破 3:1 |

这三项说明一件事：**黄系在暖白底上天然吃亏**。系统的处理不是回避黄色，而是
① 自动修正到刚好达标，② 在报告里记录修正，③ 在文档里标明「不要再调亮」。
这就是把无障碍当工程问题而非审美问题的价值。

## 4. 不只靠对比度

### 4.1 色盲与「颜色不是唯一线索」

worst case：红绿色盲（约占男性 8%）。丹青的应对是**双重保险**：

1. **色序层面**：`chart.c1…c10` 刻意避开了红绿相邻（顺序为 青→青绿→绿→黄绿→橙黄→红→品红→紫→赭→褐），
   相邻色在多数色盲模拟下仍有明度差。
2. **规则层面**：五个状态色**必须**附图标或文案。这是 WCAG 1.4.1「不能仅用颜色传达信息」的硬要求，
   也是保留族机制之外的又一道防线——因为即使色族不冲突，用户也可能分辨不出。

```html
<!-- 错 -->  <span class="tag tag-danger">已失败</span>
<!-- 对 -->  <span class="tag tag-danger"><svg class="icon-fail"/>已失败</span>
```

### 4.2 焦点可见

```css
:focus-visible {
  outline: 2px solid var(--dq-focus-ring);
  outline-offset: 2px;
  border-radius: inherit;
}
```

`focus.offset` 令牌存在的原因是：焦点环若直接贴着元素边缘，在深色表面上会与元素粘连。
偏移色必须等于所在表面色，因此它也被纳入浅/深两套语义。

**禁止** `outline: none`。如果设计上觉得默认焦点环难看，替换它，而不是删除它。

### 4.3 动效降级

```css
@media (prefers-reduced-motion: reduce) {
  :root { --dq-dur-instant: 0ms; --dq-dur-normal: 80ms; /* 其余归零 */ }
}
```

规则：位移、缩放、旋转在 `reduce` 下**全部归零**；颜色淡变保留（最长 80ms），
因为瞬时颜色跳变本身对前庭敏感用户是刺激。生成器已把这段写入 `gen/css/danqing.css`。

### 4.4 触控目标

`scale.touch.min = 44`（pt/dp），`comfortable = 48`。规则：

- 任何可点击元素的**命中区域**不小于 44×44，视觉尺寸可以更小（用透明 padding 扩展命中区）；
- 触控目标之间至少留 8 距离单位（`space.2`）；
- 密集列表行高不低于 44，表格行在触控端不低于 48。

### 4.5 字号与缩放

- 界面字号下限 12（`caption`），正文默认 14 / 移动端 16；
- 不要用 `px` 写死容器高度来容纳文字——用户把系统字号放大 200% 时容器必须能撑开；
- 阅读场景的正文字号范围 14–36（`ext.reading.fontSize`），由用户自选，不设上限阻断。

### 4.6 语言与字体回退

中文界面必须指定完整的字体回退链，否则在缺字体环境下会退到系统默认的衬线或点阵字体：

```css
font-family: var(--dq-family-ui);
/* Inter, "Noto Sans SC", "Source Han Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif */
```

最后一档必须是 `system-ui` / `sans-serif`，不能只列具体字体名。

## 5. 门禁的局限（诚实声明）

对比度门禁能挡住「不可读」，但挡不住四件事，需要人工评审：

1. **对比度过高**——纯黑文字压纯白底的 21:1 在长时间阅读时刺眼。丹青选择用 `#1E2732` 而非 `#000`
   就是出于这个考虑，但门禁不会因为「太高」而报错。
2. **色彩情绪**——门禁无法判断「这个绿色是不是太荧光了」。
3. **语义恰当性**——门禁不知道你把危险色用在了「保存成功」的提示上。
4. **状态填充上的叠字**——`on` 色只对 `default` 填充承诺 ≥4.5:1。悬停 / 按下的填充由
   `fill ± 1~2 级`派生：浅色下越按越深（白字更稳），深色下越按越亮（白字反而掉到线下）。

   | 组合 | 浅色 | 深色 |
   |---|---|---|
   | `on` on `default`（门禁项） | 13.66:1 | 5.12:1 |
   | `on` on `hover` | 13.66:1 | 3.76:1 |
   | `on` on `active` | 17.55:1 | **2.80:1** |

   这与 Material 3 的取舍一致：M3 的 state layer 只承诺 `onPrimary` 对 `primary` 容器达标，
   状态层的偏离属已知可接受范围。丹青沿用该策略，故这一组只报数、不计入退出码。

   若要收紧，正确的做法不是给 `on` 加变体——那会让文字在悬停瞬间从白翻黑，观感更差——
   而是把深色的 `primary.fill` 整体抬亮、让 `on` 本身取墨色（M3 暗色的 tonal 形态）。
   这会改变深色下 4 个品牌的视觉识别，属调色板决策，接入方不宜单方面改。

因此流程上：**门禁负责底线，评审负责上限。**
