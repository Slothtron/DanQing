Danqing · Chinese Traditional Color Design System

不产出样式，只交付
一套可验证的颜色

丹砂与青雘，是中国古代绘画的两种原色，也是「颜色这件事」最古老的代称。 丹青把这套颜色做成工程：11 个色族从传统色原值出发生成 121 级色阶， 映射为 80 个通用语义令牌，再由一个生成器导出 Windows Terminal 配色， 并用一组 WCAG 对比度门禁保证它真的可读。

它不含组件、不含平台样式代码，核心层也不含任何领域概念——阅读、播放、下单都不在其中。 领域需求走 ext.* 扩展。本页是配色参考，页面上每一个色块都取自真源。

Architecture

三层架构：原语 → 语义 → 扩展

关键在中间那一层。没有它，设计师给一张色卡，开发就得自己在 121 个色里挑、自己起名字、 自己判断哪个压得住白字——而这些判断在不同人和项目之间必然发散。

四条铁律

一个真源

tokens/source.json 是唯一人手维护的文件，产品与这里展示的一切都是它的生成物，手改会被下次生成覆盖。

只引用语义

写死 #2E59A7 与直接用原语 cn.qing.700 都是错的，只有 sys.primary.default 是对的。

深浅成对

新增语义角色必须同时给出浅色与深色两个值。深色不是浅色的反相，是换了一套材料。

颜色不单独承载信息

状态色必须附图标或文案（WCAG 1.4.1）。门禁管底线，评审管上限。

Primitives · tier 1

十一个色族，每个锚点都能溯源

锚点级直接使用传统色原值，不取推导值——这是「色彩必须有出处」最硬的落实。 其余级保持色相不变、按 OKLab 感知明度等距派生，并按距离锚点远近衰减彩度（避免亮部变荧光、暗部变死黑）。 每一级都反查了最接近的传统色名，鼠标悬停可看。

保留族机制

一个常见的严重问题：品牌色选了绿色，而系统里「成功」也是绿色 —— 用户无法仅凭颜色区分「主操作」与「操作成功」。 丹青把色族分成两类，让这种冲突在结构上不可能发生：

Brand

换品牌只改一个属性

品牌是一个受约束的开关：它只重新解析 primary.*、focus.ring、text.link， 其余 70 余个语义令牌与全部 121 个原语保持不变。点下面的卡片切换品牌， 下方预览与「终端主题」一节会跟着标记出该品牌。

「锚点保真 + 可读性回退」

优先使用锚点那一级；若该级无法同时满足「与底色 ≥3:1」与「填充上文字 ≥4.5:1」，就沿色阶向外回退最近的达标级， 并把回退步数记录下来。注意「填充上的文字」是从最亮白与最暗墨两个极端里择优—— 檀色因此得到「赭褐底 + 墨字」，而不是强行用白字（3.79:1，不达标）。

Semantic · tier 2

八十个语义令牌，两套模式

下面按角色组列出全部语义令牌，浅色值在上、深色值在下。应用代码只引用这一层， 于是「换个品牌」「换套明暗」都只是换一套解析结果，不需要改任何一处调用点。

Windows Terminal

八套终端配色：四品牌 × 明暗

这是本仓库唯一的现成产物，也是唯一入库的生成物。16 个 ANSI 槽位每个对一族、基色与亮色取同族两档， 因此色相盘不随品牌变动；品牌体现在光标与选区上。明主题的彩色槽取深墨一档（压得住纸底）， 暗主题取提亮一档（浮得出墨底）——这不是反相，是换了一套材料。

怎么用

# 1. 复制配色定义
themes/windows-terminal/danqing.schemes.json   # { "schemes": [ 8 套 ] }

# 2. 粘进 Windows Terminal 的 settings.json
#    （设置界面里也可以直接「打开 JSON 文件」后粘贴）
{ "schemes": [ ... ] }

# 3. 指定给某个 profile，或对所有 profile 生效
"profiles": { "defaults": { "colorScheme": "丹青 · 墨 · 群青" } }

# 4. 用 OS 明暗自动切换（settings.json 的顶层键）
"theme": { "dark": "丹青 · 墨 · 群青", "light": "丹青 · 素 · 群青" }

名字统一带 丹青 前缀，避免与 settings.json 里已有的配色撞名。

Data visualization

十色序列，刻意避开红绿相邻

按「青绿山水 → 暖褐」的冷暖顺序排列。图表色是字面值，因此生成器会额外校验它们与底色的对比度（≥3:1）—— 不达标就在 OKLCh 中调整明度并记录修正（本次：浅色 c4 秋香 #BF9C46 → #A9862E）。

Accessibility gates

可验优于可信

设计系统的无障碍最容易犯的错是声明式：文档里写「我们符合 WCAG AA」，但没有任何东西能阻止下一个人加一个不达标的颜色。 丹青把无障碍做成构建门禁 —— danqing build 任何一项失败即返回退出码 1。 所有前景色的 alpha 都先合成到背景再计算，因为 rgba(30,39,50,.68) 的真实观感是合成后的颜色，不是墨色本身。 终端配色同样在门禁之内：与底色同侧、用来表达底色本身的中性槽位（明主题的白、暗主题的黑）不参与同底对比， 要求它们与底色拉开对比是自相矛盾的要求；其余槽位一律按正文要求查。

Outputs
