Danqing · Chinese Traditional Color Design System

任何应用都能用的
中国传统色彩设计系统

丹砂与青雘，是中国古代绘画的两种原色，也是「颜色这件事」最古老的代称。 丹青把这套颜色做成工程：11 个色族从传统色原值出发生成 121 级色阶， 映射为 80 个通用语义令牌，再由一个脚本产出 15 种端产物， 并用 90 项 WCAG 门禁保证它真的可读。

核心层不含任何领域概念——阅读、播放、下单都不在其中。领域需求走 ext.* 扩展。

Architecture

三层架构：原语 → 语义 → 扩展

关键在中间那一层。没有它，设计师给一张色卡，开发就得自己在 121 个色里挑、自己起名字、 自己判断哪个压得住白字——而这些判断在不同人和项目之间必然发散。

TIER 1
原语 · cn.{family}.{step}
11 个中国传统色族 × 11 级色阶。锚点级写回传统色原值，每一级都反查了最接近的传统色名。无语义，不得直出到界面。

语义 · sys.{role}.{variant}
背景 / 表面 / 描边 / 文字 / 主色 / 五状态色 / 交互态 / 浮层 / 焦点 / 骨架屏 / 图表。浅深两套。应用代码唯一允许直接引用的层。

TIER 3
扩展 · ext.{domain}.{name}
领域扩展，按需引入。内置示例 ext.reading：纸色 / 正文字号 / 行高 / 行宽 / 段首缩进 —— 这些在任何通用界面里都是噪音。

四条铁律

一个真源

tokens/source.json 是唯一人手维护的文件，gen/ 全部是生成物，改了会被下次生成覆盖。

只引用语义

color:#2E59A7 与 color:var(--dq-cn-qing-700) 都是错的，只有 var(--dq-primary-default) 是对的。

深浅成对

新增语义角色必须同时给出浅色与深色两个值。深色不是浅色的反相，是换了一套材料。

颜色不单独承载信息

状态色必须附图标或文案（WCAG 1.4.1）。门禁管底线，评审管上限。

Primitives · tier 1

十一个色族，每个锚点都能溯源

锚点级直接使用传统色原值，不取推导值——这是「色彩必须有出处」最硬的落实。 其余级保持色相不变、按 OKLab 感知明度等距派生，并按距离锚点远近衰减彩度（避免亮部变荧光、暗部变死黑）。 每一级都反查了最接近的传统色名，鼠标悬停可看。

保留族机制

Brand

换品牌只改一个属性

品牌是一个受约束的开关：它只重新解析 primary.*、focus.ring、text.link， 其余 70 余个语义令牌与全部 121 个原语保持不变。点下面的卡片即可切换本页品牌。

「锚点保真 + 可读性回退」

优先使用锚点那一级；若该级无法同时满足「与底色 ≥3:1」与「填充上文字 ≥4.5:1」，就沿色阶向外回退最近的达标级， 并把回退步数记录下来。注意「填充上的文字」是从最亮白与最暗墨两个极端里择优—— 檀色因此得到「赭褐底 + 墨字」，而不是强行用白字（3.79:1，不达标）。

十色序列，刻意避开红绿相邻

按「青绿山水 → 暖褐」的冷暖顺序排列。图表色是字面值，因此生成器会额外校验它们与底色的对比度（≥3:1）—— 不达标就在 OKLCh 中调整明度并记录修正（本次：浅色 c4 秋香 #BF9C46 → #A9862E）。

Accessibility gates

可验优于可信

设计系统的无障碍最容易犯的错是声明式：文档里写「我们符合 WCAG AA」，但没有任何东西能阻止下一个人加一个不达标的颜色。 丹青把无障碍做成构建门禁 —— danqing build 任何一项失败即返回退出码 1。 所有前景色的 alpha 都先合成到背景再计算，因为 rgba(30,39,50,.68) 的真实观感是合成后的颜色，不是墨色本身。
